## 要在 Hyper-V 的 Windows 虛擬機器（VM）中執行 WSL 2 並運行 Docker 容器，需要開啟「巢狀虛擬化」（Nested Virtualization）功能。

因為 WSL 2 本身就是一個輕量級的虛擬機，當你在 Hyper-V 的 VM 裡執行 WSL 2 時，等於是在「虛擬機裡面跑虛擬機」。

以下是實現的具體步驟：

1. 開啟巢狀虛擬化 (最重要)
這必須在實體主機（Host）上操作，且該 VM 必須處於關機狀態。請以管理員權限開啟 PowerShell，輸入以下指令：

PowerShell
Set-VMProcessor -VMName "你的虛擬機名稱" -ExposeVirtualizationExtensions $true
2. VM 內的環境設定
進到虛擬機內的 Windows 後，你需要確保以下功能已開啟：

- 虛擬機器平台 (Virtual Machine Platform)
- Linux 子系統 (Windows Subsystem for Linux)

你可以透過「開啟或關閉 Windows 功能」勾選，或是使用指令：

PowerShell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
安裝完成後請重啟虛擬機。

3. 安裝 Docker Desktop 或 Docker Engine
在 VM 裡你有兩種選擇：

- Docker Desktop for Windows：最直觀，安裝時勾選「Use the WSL 2 based engine」。
- 直接在 WSL 2 (Ubuntu) 安裝 Docker Engine：如果你想節省 VM 的資源（不啟動 GUI），可以直接在 Linux 發行版內安裝原生 Docker。

## 注意事項與限制
- 硬體需求：實體機的 CPU 必須支援 VT-x (Intel) 或 AMD-V。
- 動態記憶體：在開啟巢狀虛擬化的情況下，Hyper-V VM 的「動態記憶體」功能可能會失效或不穩定，建議給予固定記憶體。
- MAC 位址欺騙：如果你在 VM 內的 Docker 需要複雜的網路橋接，可能需要在 Hyper-V 管理器的 VM 網路卡設定中開啟「啟用 MAC 位址欺騙」。

## 效能提示
由於經過了兩層虛擬化（實體機 -> Hyper-V VM -> WSL2），磁碟 I/O 和 CPU 效能會有微幅損耗。對於開發環境來說通常沒問題，但如果是高負載的正式環境，建議直接將 Docker 部署在第一層 VM 的 Linux 上，或是直接在實體機執行。
